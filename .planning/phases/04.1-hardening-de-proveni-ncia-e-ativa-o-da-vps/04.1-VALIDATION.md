| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Git snapshot, manifest, verifier checksum and image digest match on the VPS | PROV-02 | Requires inspecting the actual remote host, exact release artifacts and image built there | Compare the pinned commit/tree and ZIP, manifest and verifier hashes with the VPS verifier output; confirm the recorded image digest and release evidence in `04.1-VERIFICATION.md`. |

| Live production data and infrastructure remain unchanged through activation | DATA-01, OPS-03 | Container identity, persistent volume, migration ledger, aggregate counts and proxy are properties of the live VPS | Compare pre/post evidence in `04.1-VERIFICATION.md`; require the same PostgreSQL container and volume, ledger hash/counts and proxy, with only web/worker replaced. |
| Published version is healthy and connected to PostgreSQL after guarded release | DEP-01 | Public HTTPS, worker heartbeat and deployment outcome can only be observed against the deployed VPS | In one authorized run, record `RUN_PREVIOUS_VERSION` from the live current target, `RUN_CANDIDATE_VERSION` from the remeasured candidate attestation, and `RUN_CURRENT_VERSION` from the post-activation current target and canonical public HTTPS `/api/health`. Require current/public version to equal the candidate; rollback evidence must return current to the previous version. Record that run's `CANDIDATE_ATTESTATION_PATH`, `CANDIDATE_ATTESTATION_SHA256`, `BACKUP_ATTESTATION_REMOTE_PATH`, `BACKUP_ATTESTATION_SHA256`, and `BACKUP_ATTESTATION_EXPIRES_AT_UTC`, including freshness and candidate-binding results. |
