# Release 0.8.0 — Operação observável de notificações

**Registro atualizado:** 14/10/2026  
**Status:** validada localmente; não publicada.

## Resultado

O painel administrativo passa a mostrar o estado da fila transacional de e-mails de reserva e as falhas que esgotaram as tentativas. Isso facilita a operação na VPS sem transferir ao navegador controles de reenvio nem dados pessoais dos hóspedes.

## Escopo

- Nova seção administrativa `/painel/plataforma/notificacoes-email`, protegida pela mesma verificação de administrador usada nos outros módulos.
- Totais de `pending`, `sending`, `sent` e `failed`, além dos 20 grupos mais recentes de falhas definitivas.
- Referência curta da reserva, evento, maior número de tentativas, quantidade de destinatários, código de erro e atualização mais recente; a tela não consulta nem exibe nome ou e-mail dos destinatários.
- A leitura não afirma que o worker ou o SMTP estejam saudáveis. A tela orienta consultar os logs do container `booking-email-worker`.
- Reabertura de falhas continua no comando operacional `npm run notifications:retry-failed -- --confirm`; a interface não dispara e-mails.
- Sem alteração de banco, API pública, regras de reserva, caixa interna ou formato da outbox. Requer a migration `020_booking_email_outbox.sql` da versão 0.7.0.

## Compatibilidade e retorno

A versão 0.8.0 é compatível com o schema da 0.7.0. O retorno ao binário 0.7.0 remove a tela de monitoramento, mas preserva o schema e o consumo da fila. A migration 020 é aditiva e não deve ser revertida para voltar o código.

## Verificação

- `npm test`: 57 aprovados, 0 falhas e 3 ignorados por dependerem de POSIX/PostgreSQL.
- `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run check:architecture`, `npm run check:version` e `npm run check:vps-release` passaram para 0.8.0.
- `npm run build` e `npm run test:integration` passaram; a integração permite a nova tela para o administrador e não a mostra à conta comum.
- A consulta operacional passou em SQLite e PostgreSQL 18.6 descartável; os testes verificam contagem de estados e falhas agrupadas. O teste SQLite confirma a restrição a administradores. Os testes não usaram SMTP real.
- `docker build --tag hub-turismo-amazonas:0.8.0 --build-arg SITE_URL=https://hub.example.test .` passou. A imagem foi construída localmente, sem publicação.
- Compose descartável da 0.8.0: PostgreSQL e aplicação ficaram saudáveis, `/api/health` confirmou PostgreSQL e versão 0.8.0, a migration 020 criou `booking_email_outbox` e o worker permaneceu ativo com e-mail desligado. Containers, rede, volume e ambiente temporário foram removidos; não houve envio de e-mail.
- Não houve publicação ou acesso à VPS. A configuração SSH, o domínio e a homologação do SMTP real continuam pendentes.
